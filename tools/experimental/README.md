# Absent-service experimental slice — NO_GO / NONSHIPPING

`Invoke-AbsentServiceFixture.ps1` is a **disposable native-Windows file-staging rehearsal**, not an HP recovery command. It accepts only a specially named directory below `%TEMP%`, `-FixtureOnly`, fixed inert file names, and refuses if the service named `CabinetPlatformAgent` or the directory `C:\Program Files\Mashura\CabinetAgent` exists. It never registers or starts a service, talks to Server, enrolls a device, generates a key, edits the source copies, or writes the live install path. Its input attestation is an untrusted fixture claim, **not** evidence of original identity or SCM provenance. A synthetic `sourceCommit` and revision in tests are not the trusted candidate package. Do not substitute actual `.device` files or real credentials into fixtures.

Native fixture command (on an isolated disposable Windows VM with no Cabinet Agent):

```powershell
powershell.exe -NoProfile -File tests/office-bootstrap/AbsentServiceFixture.Tests.ps1
```

The fixture covers staging and refusal for mismatched copy bytes/digests, missing attestation, source/revision mismatch, changed candidate, advanced-journal claim, existing install, reparse source, and interrupted copy. An interrupted stage is retained, not automatically rolled back into an older journal; the original pair is untouched. On `hp-edge`/`deviceb`, an exact script ZIP staged under a new GUID-named `%TEMP%` directory ran with `powershell.exe -NoProfile -NonInteractive` and **13 fixture cases passed**, exit 0, empty stderr. The first run exposed a test-oracle mistake in the deliberately preexisting empty `work/install` case; the corrected runner passed 11 on a fresh fixture, and a later fresh run passed 13 after adding omitted `-FixtureOnly` and substituted-path refusals. These are inert file-staging observations only, not proof of original backup provenance, ACL/hardlink attack resistance, SCM registration, Agent start, Server contact, or cabinet history. Present service/install rejection is statically apparent but not natively tested (the tests must not create a real service or production install directory); ACL/hardlink adversarial cases remain untested. Thus all real recovery runtime gates remain **BLOCKED**. Each run deliberately retains its inert GUID-named temporary fixture for manual review; it performs no recursive deletion. Do not substitute real `.device` files into fixtures or treat this script as an HP restorer.

A production-capable successor needs trusted independently obtained original-machine identity and complete pre-incident SCM definition (binary path, account, start, recovery actions, dependencies, service DACL/SACL, preshutdown), protected Server snapshot plus authenticated binding/history and protocol/revision compatibility, sealed source package/digest, independently measured immutable original copies, read-only path/ACL/reparse/hardlink and host inspection, race-resistant handles and bounded SCM transaction with readback, partial-registration and post-start reconciliation, and native adversarial tests with independent review/QA. The fixture's JSON booleans, directory ACL check, and file hashes do **not** satisfy those gates. See `docs/absent-service-recovery.md`; no real HP Agent installation, identity mutation or Server write is authorized.
