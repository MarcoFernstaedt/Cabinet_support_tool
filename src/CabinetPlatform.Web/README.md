# Local browser sign-in for the Event Viewer preview

This branch uses the Windows Console's staff username and password endpoint, `POST /api/auth/login`. That endpoint is not OAuth. The browser sends the password to this loopback-only gateway. The gateway forwards it over HTTPS to the Cabinet Server, holds the short-lived access token in process memory and gives the browser an opaque, HTTP-only, SameSite=Strict cookie. Every protected request checks `/api/auth/me` again so account or session revocation can close access. The refresh token is discarded. Sign-out removes the local session, and a form token plus Origin check protect the sign-out request.

Run `npm ci` and `npm test`, then set `CABINET_WEB_LOCAL_LOGIN=1` and `CABINET_WEB_UPSTREAM` to the **HTTPS origin of a disposable Cabinet Server test instance bound to 127.0.0.1 or ::1**. Run `npm start` and open `http://127.0.0.1:4173` on the same machine. Do not paste real credentials into source code, command arguments or chat. Do not point this build at a production server, including through a local tunnel or reverse proxy. The loopback-origin check blocks a direct remote upstream but cannot prove that the upstream database holds only synthetic records. Verify its database and test accounts before running it. The preview refuses non-loopback binding, remote upstream URLs and startup without explicit opt-in. The browser connection is plain HTTP over loopback, so do not forward the port or browse from another computer.

## Supervisor enrollment and retirement (synthetic preview)

The Supervisor queue at `/enrollment` pages pending registrations. Its approval and rejection confirmations show the registration, reported hostname and machine ID. Cabinet detail links to `/cabinet/{id}/retire` for a separate retirement confirmation. The gateway accepts only exact GUID routes and bounded form fields, checks the exact browser Origin and the session's random CSRF token on each POST, rechecks active Supervisor status through `/api/auth/me`, and reads the target again before sending a narrow JSON request. It does not send or display enrollment tokens, device keys or browser bearer tokens. Server authorization and its conditional pending-status decision remain authoritative. Refreshing a queue or cabinet before POST is not an atomic precondition; a concurrent decision can still win. On a refused or uncertain outcome, inspect the fresh queue/detail before attempting another confirmation. Retirement disables operational access and retains history; credential erasure on the device is unverified.

Approval takes client, site, department and one of Sync, Satellite or Standalone. The preview requires a nonblank reason and sends it as `approvalReason`; the Server records the trimmed reason in the named Supervisor approval audit. Older clients can omit this optional contract field. Rejection and retirement reasons are transmitted in their exact request contracts. There is no MFA, independent staff-to-cabinet authorization, production ingress protection or live Windows acceptance. Do not use this gateway against real cabinets, credentials or customer data, even via a loopback forward. This preview has no remote control feature.

The display preview at `/cabinet/{id}/display` reads only a saved, bounded `GetDisplayDiagnostics` action for that cabinet, with an action-pinned link so a later collection cannot replace the selected result. OS modes visible to the Agent service are not proof of the active user's effective display state. Scaling, Magnifier and app zoom are separately unknown when a reliable session-aware source is unavailable; this page offers no display correction or remote access. Native Windows service context and browser accessibility are not yet tested.

The storage preview at `/cabinet/{id}/storage` uses a narrow, audited cabinet-bound Server projection of the latest heartbeat disk summary, privacy-limited inventory volume observations and up to 32 retained SMART readings. It does not expose serials, drive letters, models, raw inventory or collector errors. Embedded free-space values belong to an inventory version's first observation, not the later confirmation; the heartbeat's disk verdict can be carried from an older full collection. SMART receipt time is not persisted, and the shown dominant source is not field-level provenance. Missing counters and missing drives are unknown rather than healthy, and a retained drive could have been removed. This is only a historical disposable-data preview, without a per-drive trend or staff authorization.

The default Event Viewer at `/` still displays clearly labelled fictional records for layout testing. From a cabinet detail page, `/cabinet/{id}/events` instead reads the latest saved `RunEventLogView` result for that exact cabinet through a narrow, bounded Server projection. It does not request a new action or blend fictional records with collected results. The network history page at `/cabinet/{id}/network-history` uses a bounded, cabinet-scoped accepted-interval read with observed-time cursor and optional exact target filter. It keeps Agent observation and Server receipt separate, labels retained replies and local probe errors, and does not infer a complete outage timeline or recovery onset from missing rows. Late replay and retention mean pagination is not an immutable snapshot. The read-only incident evidence page at `/incident/{id}/correlation` pins an alert to its accepted interval and directed source/target cabinet identities. It shows server contact, separately timed heartbeat collection/receipt, current topology and any accepted coarse source firewall-profile clue without inferring simultaneity, firewall cause, application sync or measured recovery. It explicitly marks application-port evidence as not collected. The fleet and site health page at `/fleet/health` is a separate local-only overview. It paginates active cabinets and sites, labels contact time separately from the latest heartbeat collection/receipt, distinguishes never-measured and stale measurements from Unknown health, and shows historical sync reachability without assuming firewall causation. Site order is stable by client/site identity rather than incorrectly claiming fleet-wide severity order. Summary and pages are separate reads, not a transactionally consistent snapshot; a mismatch is treated as unavailable rather than as a false count. Fleet-scale PostgreSQL latency and browser accessibility are unverified. The local Fleet finder, cabinet detail, site incident, saved event, crash-clue and process/service pages make bounded read-only server requests with the bearer token held by the gateway, not browser JavaScript. The process page shows an exact cabinet-bound, action-pinned `GetProcessList` projection with only image name, PID and nullable counters; it never exposes executable path or selection identity. It also shows retained service names/states from the current inventory version, with first and last observation times. An unchanged inventory can retain an old PID, so the page does not display or match service PIDs to process rows. Neither process action completion nor service inventory confirmation proves live state or crash-time presence. No process or service controls are exposed. The crash page is an incomplete workflow: it lists only saved Application Error and Windows Error Reporting event metadata, not a structured WER report or historical process evidence, and never asserts a cause. Links to exact collected events use a cabinet-bound saved action ID, so a newer collection cannot silently replace the selected event; a retained action that is removed returns not found. A missing, pending, failed, partial or truncated event result is labelled rather than shown as an empty success; older records are not substituted when a newer request is pending. The Server policy remains role-wide, not staff-to-cabinet authorization. These are development test surfaces and must use synthetic cabinets only. No annotations, generic API proxy, file access or remote control are exposed. This password-only flow has no MFA and is **not approved for deployment or real support work**. Before making a browser Console available to staff, replace this development-only gateway with the reviewed Entra MFA flow, enforce immutable Cabinet staff mapping and per-cabinet authorization, and test real tenant policy, secure sessions, revocation, auditing, representative fleet performance, Windows Agent-to-Server-to-web transport and native browser accessibility. The separate Entra host has no cabinet data routes. The WPF Console remains the operational UI.
