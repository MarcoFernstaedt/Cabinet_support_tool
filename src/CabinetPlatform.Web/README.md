# Local browser sign-in for the Event Viewer preview

This branch uses the Windows Console's staff username and password endpoint, `POST /api/auth/login`. That endpoint is not OAuth. The browser sends the password to this loopback-only gateway. The gateway forwards it over HTTPS to the Cabinet Server, holds the short-lived access token in process memory and gives the browser an opaque, HTTP-only, SameSite=Strict cookie. Every protected request checks `/api/auth/me` again so account or session revocation can close access. The refresh token is discarded. Sign-out removes the local session, and a form token plus Origin check protect the sign-out request.

Run `npm ci` and `npm test`, then set `CABINET_WEB_LOCAL_LOGIN=1` and `CABINET_WEB_UPSTREAM` to the **HTTPS origin of a disposable Cabinet Server test instance bound to 127.0.0.1 or ::1**. Run `npm start` and open `http://127.0.0.1:4173` on the same machine. Do not paste real credentials into source code, command arguments or chat. Do not point this build at a production server, including through a local tunnel or reverse proxy. The loopback-origin check blocks a direct remote upstream but cannot prove that the upstream database holds only synthetic records. Verify its database and test accounts before running it. The preview refuses non-loopback binding, remote upstream URLs and startup without explicit opt-in. The browser connection is plain HTTP over loopback, so do not forward the port or browse from another computer.

The default Event Viewer at `/` still displays clearly labelled fictional records for layout testing. From a cabinet detail page, `/cabinet/{id}/events` instead reads the latest saved `RunEventLogView` result for that exact cabinet through a narrow, bounded Server projection. It does not request a new action or blend fictional records with collected results. The local Fleet finder, cabinet detail, site incident, saved event and crash-clue pages make bounded read-only server requests with the bearer token held by the gateway, not browser JavaScript. The crash page is an incomplete workflow: it lists only saved Application Error and Windows Error Reporting event metadata, not a structured WER report or historical process evidence, and never asserts a cause. Links to exact collected events use a cabinet-bound saved action ID, so a newer collection cannot silently replace the selected event; a retained action that is removed returns not found. A missing, pending, failed, partial or truncated event result is labelled rather than shown as an empty success; older records are not substituted when a newer request is pending. The Server policy remains role-wide, not staff-to-cabinet authorization. These are development test surfaces and must use synthetic cabinets only. No annotations, generic API proxy, file access or remote control are exposed. This password-only flow has no MFA and is **not approved for deployment or real support work**. Before making a browser Console available to staff, replace this development-only gateway with the reviewed Entra MFA flow, enforce immutable Cabinet staff mapping and per-cabinet authorization, and test real tenant policy, secure sessions, revocation, auditing, representative fleet performance, Windows Agent-to-Server-to-web transport and native browser accessibility. The separate Entra host has no cabinet data routes. The WPF Console remains the operational UI.
