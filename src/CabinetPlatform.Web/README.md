# Local browser sign-in for the Event Viewer preview

This branch uses the Windows Console's staff username and password endpoint, `POST /api/auth/login`. That endpoint is not OAuth. The browser sends the password to this loopback-only gateway. The gateway forwards it over HTTPS to the Cabinet Server, holds the short-lived access token in process memory and gives the browser an opaque, HTTP-only, SameSite=Strict cookie. Every protected request checks `/api/auth/me` again so account or session revocation can close access. The refresh token is discarded. Sign-out removes the local session, and a form token plus Origin check protect the sign-out request.

Run `npm ci` and `npm test`, then set `CABINET_WEB_LOCAL_LOGIN=1` and `CABINET_WEB_UPSTREAM` to the **HTTPS origin** of a disposable Cabinet Server test deployment. Run `npm start` and open `http://127.0.0.1:4173` on the same machine. Do not paste real credentials into source code, command arguments or chat. Do not point this build at a production server. It refuses non-loopback binding, non-HTTPS upstream URLs and startup without an explicit opt-in. The browser connection is plain HTTP over loopback, so do not forward the port, reverse proxy it, or browse from another computer.

Sign-in is the only connected operation. The Event Viewer still displays clearly labelled fictional records. There are no live cabinet API routes, actions or remote access. This password-only flow has no MFA and is **not approved for deployment or real support work**. Before making a browser Console available to staff, replace this development-only gateway with the reviewed Entra MFA flow, enforce Cabinet staff mapping and authorization, and test real tenant policy, secure sessions, revocation, auditing and the first cabinet data adapter. The separate Entra draft PR remains deferred, not silently merged. The WPF Console remains the operational UI.
