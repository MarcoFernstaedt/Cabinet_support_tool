# Web Console sign-in boundary

This is a separate ASP.NET Core web host for the first feature, staff sign-in. It does not serve the synthetic UI preview or contact the Cabinet API. The previous preview remains loopback-only and is not an authenticated support app.

The host refuses startup without `WebConsole__Entra__TenantId`, `WebConsole__Entra__ClientId`, `WebConsole__Entra__ClientSecret` and `WebConsole__Entra__RequiredAuthContext` supplied through a deployment secret store or process environment. Do not put a client secret in tracked settings or messages. Register a **single-tenant web application** in the organization's Microsoft Entra tenant with an HTTPS redirect URI ending `/signin-oidc` and a post-logout redirect URI ending `/signout-callback-oidc`. An Entra administrator must create and enforce the named Conditional Access authentication context (for example `c1`) for this application, confirm it requires MFA with an approved method, assign permitted staff, and verify recovery and revocation. Merely having Microsoft Authenticator installed is not proof that this sign-in meets the policy. The tenant ID, app ID and context name are not secrets, but verify them with the administrator rather than guessing. Use a secret store for the app credential, not an email or chat attachment.

The sign-in uses OIDC authorization code with PKCE, pins the tenant issuer and client audience, requests the specified `acrs` claim, and refuses the identity if the tenant, object ID or context is absent. The browser receives only a Secure, HttpOnly, SameSite cookie with a 30-minute fixed lifetime. Tokens are not saved in browser storage. Anonymous data routes are not registered; missing configuration is a startup failure. Logout is a CSRF-protected POST with local and provider sign-out requests. The homepage proves only that the Entra identity met the requested context; it does **not** grant a Cabinet staff role.

Run the focused tests with `dotnet test tests/CabinetPlatform.WebHost.Tests/CabinetPlatform.WebHost.Tests.csproj`. A synthetic OIDC discovery document is used in tests; no actual Entra login was performed. Before any staff deployment, independently validate the real tenant Conditional Access configuration and token contents, authenticated browser callback, logout and deactivation, secure shared Data Protection key persistence, HTTPS reverse-proxy forwarding, staff subject to Cabinet user mapping, audit and access denial, and an end-to-end read-only Event Viewer path. No production release or replacement of WPF is authorized by this project.
