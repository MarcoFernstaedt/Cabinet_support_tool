# Independent office demo kit

This unsigned, source-bound kit contains one self-contained Windows x64 Agent ZIP, a first-install PowerShell helper, issuance and renewal tools, and the server and renewal guides. It does not contain a desktop operator application. It is a bounded lab demo, not a production deployment. Its Agent is a C# Windows service; PowerShell 5.1 is required to run the administrator first-install helper, not to run the Agent. Building Windows executables on Linux does not certify Windows 10 behavior. Windows 10 and Windows 11 native Agent install and TLS acceptance remain open. Do not install on a customer cabinet or overwrite the working HP Agent.

For the specific HP absent-service/absent-install state, [the read-only recovery hold](absent-service-recovery.md) documents evidence gaps and a NO-GO triage; it is not an installer or deployment approval. Same-device upgrade, uninstall and manual reinstall are unsupported in this minimal kit. The experimental source and fixtures remain in Git for separate review, but `Restore-CabinetDemoAgent.ps1`, `Manual-Reinstall-CabinetDemoAgent.ps1` and `RecoveryProcess.cs` are not distributed. Renewal extends the existing protected device credential; it does not reinstall an Agent or repair a lost key. Marco has not personally approved giving up the same-device manual walkthrough; this reduced kit cannot supply it. Do not rename reinstall as upgrade or use the first-install helper on the HP.

## Build and verify the Agent-only kit

On an authorized build host, build an exact committed revision with `python3 -B tools/build_independent_demo_kit.py --output /home/marco/tmp/cabinet-kit-NEW --dotnet /home/marco/tmp/cabinet-audit-dotnet/dotnet`. The builder archives HEAD rather than reading worktree edits and publishes only the Release `win-x64` self-contained Agent. It does not issue tokens, install a service or contact the server. The kit has eight inventoried deliverables and `release-evidence.json`. The Agent ZIP has a complete `kit-manifest.json` with the source commit and member hashes. These hashes are integrity checks, not signatures. Obtain the reviewed commit and digests over a trusted channel separate from the kit, then compare the files before execution. The kit and server must use the exact matching reviewed Office revision. The Agent `appsettings.json` points at `https://srv1522777.tail72f980.ts.net/`; verify HTTPS trust and the server's actual configuration, not just its health endpoint. A public ingress URL is not an access control.

Operator access and pending enrollment approval require the separately reviewed server/browser staff workflow; this kit does not deliver or certify that workflow. Use a named authorized test staff account through its normal sign-in path, and stop if approval is unavailable. No staff password is in the kit.

## New device only: issue, install and approve

The authorized server operator first follows `independent-demo-server.md` to verify the matching Office mode, private consumed grant journal, configuration and recovery route. From a controlled server environment, run `python3 -B issue_office_enrollment.py --manifest <private-absolute-manifest> --output <new-private-absolute-device-file>`. The helper appends a token hash and writes a unique one-device token file; it does not restart the server. Obtain separate approval for a restart of the reviewed test service and verify it loaded the manifest. Transfer the token file through a private approved channel, never in the kit, chat, repository or shared image. Put it in a protected local administrator directory that grants access only to Administrators and SYSTEM. The unused enrollment token expires 20 minutes after issuance. The initial device credential expires 24 hours after issuance, even if enrollment occurred later. Do not extend timestamps, clone a key, reset the journal or use a shared fleet secret.

On a fresh, separate, authorized disposable Windows x64 lab machine, verify the Agent ZIP and `Install-CabinetDemoAgent.ps1` SHA-256 against independently trusted release evidence. Use elevated built-in Windows PowerShell 5.1, with the local script and software policy permitting unsigned code. If policy blocks it, stop; do not bypass SmartScreen, antivirus or execution policy. Run from the transferred kit directory:

```powershell
& .\Install-CabinetDemoAgent.ps1 -AgentZip .\cabinet-agent.zip -EnrollmentFile C:\PrivateToken\device.json -ExpectedSha256 <trusted-64-hex-agent-zip-digest> -ExpectedSourceCommit <reviewed-40-hex-commit>
```

Replace the placeholders with the exact independently verified values; never enter the token value on the command line. The helper refuses an existing service or install folder, an untrusted ancestor or token ACL, a reparse path, unsafe or duplicate ZIP entries, a changed configuration, a wrong commit, endpoint or digest. It hashes and reads through one protected ZIP stream. It installs under `C:\Program Files\Mashura\CabinetAgent`, sets private file and directory permissions, copies the token locally, creates a quoted LocalSystem automatic service with recovery settings, reads back registration and requests start. It does not print the token. The source token remains the operator's responsibility for secure local disposal. A failure before registration removes only this run's new directory; after registration it preserves the secured installation for inspection. Never rerun over a partial install.

A Running service is not proof of enrollment. Read back the service account, automatic start, exact quoted executable path and effective install ACLs. An authorized Supervisor must select and approve the expected pending machine through the separately reviewed browser staff workflow; do not substitute this kit for approval authority. Verify fresh authenticated server contact under its exact cabinet UUID and machine identity, an Agent restart retaining the same identity, and persisted history. Do not equate pending with approved or approved with current diagnostics. The already enrolled HP stays installed, with its original key, state and history untouched.

## Repeat demo and failure handling

For an approved active same device retaining its original protected `.device` key and server history, use `office_renewal_operator.py` from the authorized operator workstation with masked credential entry. Follow `demo-credential-renewal.md` for confirmation, an exact saved-decision retry after uncertain responses, and `office_renewal_preflight.py` before server configuration changes. A renewal decision lasts 24 hours and is capped at 30 decisions per device; it is manual, not automatic fleet renewal. A missing key or suspected compromise is not a renewal case. The first-install helper cannot restore an existing cabinet or reuse its historical identity.

If enrollment refuses, check expiry, matching server revision, Office mode, manifest reload, TLS, existing identity and journal agreement without showing secrets. Preserve the exact nonsecret error, commit and package digest. Do not clear a journal, reinstall over an enrolled machine or convert a same-device repair into fresh enrollment. Removal or reinstall requires a separate reviewed procedure and authorization; none is distributed here. For an unused failed lab install, inspect the service and identity and follow a separately authorized retention and cleanup decision, not an ad hoc deletion. The server operator must preserve consumed journal and cabinet audit history.

## Remaining acceptance

From the exact revision, run `Test-InstallerSnapshot.ps1` and `Test-InstallerHelpers.ps1` under Windows PowerShell 5.1, then elevated `Test-InstallerPreflight.ps1` on a fresh authorized disposable lab. The first two use inert temporary ZIPs and selected installer functions; the preflight checks a wrong-digest refusal before install writes. They do not prove service creation or enrollment. Separately test inherited private token ACLs, shared read-only vendor parent, writable/reparse ancestor refusals, corrupted or duplicate ZIP/JSON, existing identity/service refusal, native `sc.exe` quoting, recovery and rollback under induced failures. Complete fresh install, browser staff approval, restart and authenticated telemetry/history remain separate gates. No Windows 10 VM was installed or native certified for this package. The HP Agent is not a disposable fixture.

Production deployment for thousands of cabinets needs signed unattended installation through authorized management, scoped enrollment, automatic renewal, safe updates/rollback and fleet status. This manual kit implements none of those controls. Do not distribute it as production software.
