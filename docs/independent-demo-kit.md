# Independent office demo kit

This is a first install on one authorized disposable Windows lab PC, not an upgrade or a fleet installer. The published main release remains unchanged. Do not use the existing HP Agent installation as a test target. Do not copy its key, state, configuration or installed binaries. The test service must already run the matching reviewed Office server mode; the server health response alone does not prove that.

## Build and transfer

On the authorized build host, commit and review the kit, then build from that exact committed revision:

```sh
python3 tools/build_independent_demo_kit.py --output /home/marco/tmp/cabinet-kit-NEW --dotnet /home/marco/tmp/cabinet-audit-dotnet/dotnet
sha256sum /home/marco/tmp/cabinet-kit-NEW/cabinet-*.zip
```

The builder archives HEAD, publishes win-x64 Release self-contained Agent and WPF Console, and creates new-only credential-free ZIPs. The output also includes the exact committed `Install-CabinetDemoAgent.ps1`, this guide, and `release-evidence.json` with the commit and SHA-256 for all four files. It does not read the dirty worktree solution, issue a token, install a service or contact a live server. Each ZIP contains `kit-manifest.json` with a source commit and the exact SHA-256 inventory. The builder checks its ZIP after writing it. Neither the manifest nor `release-evidence.json` is a signature. Deliver the reviewed source commit and all four hashes over a trusted channel separate from the kit. Before running the elevated helper, compare its hash and the Agent ZIP hash to that trusted evidence; do not trust a hash found only next to the file it describes. The Console ZIP is a generic operator app: verify its digest from trusted release evidence, extract to an authorized workstation folder, inspect its `appsettings.json` endpoint and launch the executable. It has no username or password. Use a named test account issued through the normal staff flow.

Endpoint for both packages: `https://srv1522777.tail72f980.ts.net/`. Confirm the matching server revision, Office mode pin and HTTPS trust before attempting enrollment. The URL may use public ingress; do not mistake tailnet DNS for an access control. These packages are unsigned. Resolve the organization's unsigned artifact policy explicitly before running them. If policy denies execution, stop. Do not disable antivirus, SmartScreen or script policy.

## Issue one device token on the server

The authorized server operator uses the existing `tools/issue_office_enrollment.py --manifest <private absolute server manifest> --output <new private absolute device file>` in its controlled environment. The manifest and its consumed grant journal must remain private and preserved. The tool appends a hash and writes one new token file; it does not restart the server. Obtain explicit approval for a restart of only the reviewed test service, and verify that it loaded the changed manifest. Transfer the one device JSON by a separate approved private channel. Never put it in the ZIP, source control, chat, public downloads or a shared machine image. The installer requires the token file and its parent to permit only Administrators and SYSTEM; have the receiving administrator place it in a protected local directory and verify effective ACLs before running the helper. Do not send its token value in diagnostics.

The unused token expires 20 minutes after issuance. The device credential expires 24 hours after issuance, even if enrollment occurred later. There is no automatic renewal. The tool retains the consumed journal and refuses an existing machine identity. Do not extend the timestamps, reset the journal, clone a device key or use a shared fleet secret to continue a demo. Issue a fresh token shortly before a fresh first install on a different disposable lab identity. An enrolled identity cannot simply be reenrolled. A repeat demo on that identity after expiry is blocked until a separately reviewed renewal protocol exists; use the existing enrollment only within its validity window.

## First install on Windows

Use a clean Windows 10/11 disposable lab machine with x64, elevated Windows PowerShell 5.1, and the verified helper, Agent ZIP, source commit and Agent ZIP SHA-256. No PowerShell 7 installation is required. The helper is not a double-click installer. Run only when the local script policy and organizational software policy permit the reviewed script. If either blocks it, stop and request approval through normal channels; do not bypass the policy. The signed installer and managed deployment flow are separate work. On the lab machine, in the transferred kit directory, check `(Get-FileHash -Algorithm SHA256 -LiteralPath .\Install-CabinetDemoAgent.ps1).Hash` and `(Get-FileHash -Algorithm SHA256 -LiteralPath .\cabinet-agent.zip).Hash` against the separately trusted release evidence before elevation. Verify the guide and Console ZIP hashes as well.

```powershell
& .\Install-CabinetDemoAgent.ps1 -AgentZip .\cabinet-agent.zip -EnrollmentFile C:\PrivateToken\device.json -ExpectedSha256 <trusted-64-hex-agent-zip-digest> -ExpectedSourceCommit <reviewed-40-hex-commit>
```

The helper refuses nonadministrators, existing service or install folder, reparse paths, unsafe/duplicate ZIP entries, incomplete hashes, changed configuration, wrong source revision and wrong endpoint. It retains a read-only ZIP handle denying write/delete while hashing and reading the same archive stream. It checks the manifest and every ZIP member before writing. Secret file ACLs may inherit only trusted SYSTEM/Administrators access. Existing executable ancestors must have trusted ownership and no untrusted mutation rights; ordinary read/execute on a shared `Mashura` parent is allowed and the helper does not change that existing parent's ACL. A rejected path and SID are shown without printing token bytes. It uses the fixed `C:\Program Files\Mashura\CabinetAgent` path, locks the new child directories and files to Administrators and SYSTEM, copies the enrollment file without printing it, creates a quoted LocalSystem automatic service with recovery and starts it. No arbitrary command from an archive is executed. The source token file remains with its operator until secure deletion through the approved local procedure. If a failure occurs before service registration, the helper removes only its newly created install directory. If registration has occurred, it preserves secured files and any device identity for inspection. Do not rerun over a partial install or delete state to make it pass.

## Check the result

`Get-Service CabinetPlatformAgent` showing Running proves only a process started. Check `Get-CimInstance Win32_Service -Filter "Name='CabinetPlatformAgent'"` for `LocalSystem`, automatic start and the quoted fixed executable path. Check effective ACLs with `icacls` on the install folder and `office-enrollment.json.device` after first exchange. Read only redacted Agent logs in `logs` and verify its HTTPS contact. On the Console, a supervisor checks the pending queue, matches the expected machine identity and site, and explicitly approves it. Confirm the same cabinet ID survives an Agent restart and a fresh authenticated check-in appears after approval. Pending is not approved; approved is not proof that current diagnostics have arrived. Test a second unrelated machine/key denial in a lab before broader claims.

A refused token can mean it expired, the server was not restarted after issuance, the matching Office mode is not active, TLS failed, the machine identity already exists, or the manifest and durable grant journal disagree. Check those conditions without printing credentials. A lost HTTP response can be retried by the same persisted machine/key pair within the device deadline. An expired credential has no renewal path here. Logs and service state do not substitute for an authenticated server readback. Preserve the exact error, package digest and source revision for review. Do not reset the journal or install over an identity.

For removal of an unused failed install, inspect whether the service and identity exist before acting. For an enrolled lab, the server operator first removes that device's token hash from the active manifest and restarts the reviewed test service under separate authorization. Confirm the old credential is rejected. Keep the consumed journal and cabinet audit history. Then stop and delete the lab service, retain a protected evidence copy of state if required, and remove its lab files according to retention policy. Do not delete a live installation, customer history or the HP Agent. Rollback to a shared-key server is not safe for this identity mode.

## Native acceptance still required

From the exact committed source on an authorized disposable Windows 10 and Windows 11 lab machine, run `& .\tests\office-bootstrap\Test-InstallerSnapshot.ps1` in Windows PowerShell 5.1. It uses an inert temporary ZIP to check that the retained handle denies writes and replacement while the same stream is hashed and parsed. On a fresh disposable lab machine, run `& .\tests\office-bootstrap\Test-InstallerPreflight.ps1` elevated. It parses the helper and checks a wrong-digest refusal before any install write. Neither test enrolls a device. Then separately test secure inherited token ACLs, a shared vendor parent with read-only user ACEs, user-writable and reparse ancestors, corrupted/duplicate JSON and ZIP, existing identity and service, and `sc.exe` path quoting/recovery readback. Inject registration, recovery and start failures on disposable machines only. Fresh installation, approval, restart and authenticated telemetry require the authorized matching test server and are not certified by these portable tests. Do not run this matrix on the working HP.

## Fleet deployment is separate

A production deployment across roughly 8,000 cabinets needs a signed installer, unattended deployment through an authorized management platform (platform not selected), per-device scoped onboarding and automatic credential renewal, safe updates and rollback with fleet status, and a reviewable revocation and recovery protocol. No shared fleet secret, remote session or manual script on every cabinet, and no unrestricted shell. This kit implements none of those production controls. Native Windows 10/11 install, ACL, PowerShell, WPF, TLS, refusal and removal checks remain an independent lab acceptance gate before distributing even the bounded demo kit.
