# Independent office demo kit

The first-install helper is for one new authorized disposable Windows lab PC, not an upgrade or fleet installer. `Restore-CabinetDemoAgent.ps1` is a separate same-device upgrade helper that retains the service registration for an existing approved lab installation. Do not run the first-install helper over the HP Agent or erase its original key, state, server identity or history. The test service must run the matching reviewed Office server mode; health alone does not prove that. See independent-demo-server.md for the gated VPS procedure and demo-credential-renewal.md for repeat demos.

## Build and transfer

On the authorized build host, commit and review the kit, then build from that exact committed revision:

```sh
python3 tools/build_independent_demo_kit.py --output /home/marco/tmp/cabinet-kit-NEW --dotnet /home/marco/tmp/cabinet-audit-dotnet/dotnet
sha256sum /home/marco/tmp/cabinet-kit-NEW/cabinet-*.zip
```

The builder archives HEAD, publishes win-x64 Release self-contained Agent and WPF Console, and creates new-only credential-free ZIPs. The output also includes the exact committed first-install and recovery helpers, issuance, renewal and preflight tools, this guide, the renewal and server guides, and `release-evidence.json` with the commit and SHA-256 for all ten deliverables. It does not read the dirty worktree solution, issue a token, install a service or contact a live server. Each ZIP contains `kit-manifest.json` with a source commit and the exact SHA-256 inventory. The builder checks its ZIP after writing it. Neither the manifest nor `release-evidence.json` is a signature. Deliver the reviewed source commit and all ten hashes over a trusted channel separate from the kit. Before running the elevated helper, compare its hash and the Agent ZIP hash to that trusted evidence; do not trust a hash found only next to the file it describes. The Console ZIP is a generic operator app: verify its digest from trusted release evidence, extract to an authorized workstation folder, inspect its `appsettings.json` endpoint and launch the executable. It has no username or password. Use a named test account issued through the normal staff flow.

Endpoint for both packages: `https://srv1522777.tail72f980.ts.net/`. Confirm the matching server revision, Office mode pin and HTTPS trust before attempting enrollment. The URL may use public ingress; do not mistake tailnet DNS for an access control. These packages are unsigned. Resolve the organization's unsigned artifact policy explicitly before running them. If policy denies execution, stop. Do not disable antivirus, SmartScreen or script policy.

## Issue one device token on the server

The authorized server operator uses the delivered `issue_office_enrollment.py --manifest <private absolute server manifest> --output <new private absolute device file>` in its controlled environment, only after the server runbook gates. The manifest and its consumed grant journal must remain private and preserved. The tool appends a hash and writes one new token file; it does not restart the server. Obtain explicit approval for a restart of only the reviewed test service, and verify that it loaded the changed manifest. Transfer the one device JSON by a separate approved private channel. Never put it in the ZIP, source control, chat, public downloads or a shared machine image. The installer requires the token file and its parent to permit only Administrators and SYSTEM; have the receiving administrator place it in a protected local directory and verify effective ACLs before running the helper. Do not send its token value in diagnostics.

The unused token expires 20 minutes after issuance. The initial device credential expires 24 hours after issuance, even if enrollment occurred later. There is no automatic renewal. The tool retains the consumed journal and refuses an existing machine identity. Do not extend the timestamps, reset the journal, clone a device key or use a shared fleet secret to continue a demo. Issue a fresh token shortly before a fresh first install on a different disposable lab identity. An enrolled identity cannot simply be reenrolled. For an approved active same device with its original protected key and previous history, use the delivered manual renewal operator and exact-decision retry procedure in demo-credential-renewal.md. Each authorized decision lasts 24 hours and is capped; it does not mint another device identity. If its key is missing or compromise suspected, stop rather than using a fresh token.

## First install on Windows

Use a clean Windows 10/11 disposable lab machine with x64, elevated Windows PowerShell 5.1, and the verified helper, Agent ZIP, source commit and Agent ZIP SHA-256. No PowerShell 7 installation is required. The helper is not a double-click installer. Run only when the local script policy and organizational software policy permit the reviewed script. If either blocks it, stop and request approval through normal channels; do not bypass the policy. The signed installer and managed deployment flow are separate work. On the lab machine, in the transferred kit directory, check `(Get-FileHash -Algorithm SHA256 -LiteralPath .\Install-CabinetDemoAgent.ps1).Hash` and `(Get-FileHash -Algorithm SHA256 -LiteralPath .\cabinet-agent.zip).Hash` against the separately trusted release evidence before elevation. Verify the guide and Console ZIP hashes as well.

```powershell
& .\Install-CabinetDemoAgent.ps1 -AgentZip .\cabinet-agent.zip -EnrollmentFile C:\PrivateToken\device.json -ExpectedSha256 <trusted-64-hex-agent-zip-digest> -ExpectedSourceCommit <reviewed-40-hex-commit>
```

The helper refuses nonadministrators, existing service or install folder, reparse paths, unsafe/duplicate ZIP entries, incomplete hashes, changed configuration, wrong source revision and wrong endpoint. It retains a read-only ZIP handle denying write/delete while hashing and reading the same archive stream. It checks the manifest and every ZIP member before writing. Secret file ACLs may inherit only trusted SYSTEM/Administrators access. Existing executable ancestors must have trusted ownership and no untrusted mutation rights; ordinary read/execute on a shared `Mashura` parent is allowed and the helper does not change that existing parent's ACL. A rejected path and SID are shown without printing token bytes. It uses the fixed `C:\Program Files\Mashura\CabinetAgent` path, locks the new child directories and files to Administrators and SYSTEM, copies the enrollment file without printing it, creates a quoted LocalSystem automatic service with recovery and starts it. No arbitrary command from an archive is executed. The source token file remains with its operator until secure deletion through the approved local procedure. If a failure occurs before service registration, the helper removes only its newly created install directory. If registration has occurred, it preserves secured files and any device identity for inspection. Do not rerun over a partial install or delete state to make it pass.

## Same-device upgrade with retained service registration

`Restore-CabinetDemoAgent.ps1` is only for the existing enrolled machine, with `CabinetPlatformAgent` running under LocalSystem, automatic start, the quoted fixed executable path, private install tree and an original confirmed `.device` journal matching the persisted machine identity and reviewed HTTPS endpoint. It does not take a token or copy a credential from another machine. Use an independent recovery route and approved maintenance window. Do not run it on a customer cabinet. Verify the exact Agent ZIP and helper digests against separately trusted release evidence, the original cabinet UUID and server history through supported operator APIs, and the local original install and service baseline before granting the maintenance window. The script does not verify server history or credential validity.

Run elevated built-in Windows PowerShell 5.1 on the SAME MACHINE. Choose an existing private Administrators/SYSTEM-only local backup parent off Desktop, outside the installation and ZIP paths. Never use a remote share or a directory holding another machine's state. The helper requires explicit parameters and refuses a default invocation:

```powershell
& .\Restore-CabinetDemoAgent.ps1 -ConfirmSameMachine -AgentZip C:\PrivateKit\cabinet-agent.zip -ExpectedSha256 <independently-trusted-agent-zip-digest> -ExpectedSourceCommit <reviewed-source-commit> -BackupRoot C:\PrivateAgentRecovery
```

This is an upgrade, not a removal/reinstall or universal service restoration utility. The original SCM registration stays in place, including its display name, description, recovery actions and security descriptor. The helper only changes startup type temporarily. It admits the HP's captured zero-action policy and supported none/restart policies semantically, not by localized sc.exe output. Dependencies, delayed start, custom privileges, service SID, triggers and custom DACLs still require separate review and are refused before stopping. It does not recreate or claim to reconstruct optional SCM metadata or SACLs.

The script holds one read-only package stream that denies replacement while validating the digest and complete inventory. It disables startup before gracefully stopping, captures a private original tree, replaces package members by exact relative path and restores all original non-package state before first start. It compares preserved membership and content, service policy and display name, then requests manual start and restores automatic startup only after Running. No forced process kill, fresh enrollment or server write is part of this helper.

Trust boundary: administrators and SYSTEM, the reviewed installed Agent and the operating system are trusted. This is not a sandbox against an administrator who can already replace binaries or credentials. The helper checks machine registry environment names and refuses any per-service Environment value. On x64 Windows it reads the actual running LocalSystem Agent environment with query/read-only process handles, verifies the executable, arguments, working directory and current services.exe parent, and rejects configuration keys and runtime hooks/profilers. It never treats the operator shell as SCM evidence. Registry sources are checked again before start. RecoveryProcess.cs must remain beside the helper and its release digest must be verified with the helper's digest.

There is no public .NET API for another process's environment: ProcessStartInfo.Environment configures a future child only. The bounded reader uses native x64 PEB offsets, caps reads and refuses inaccessible or unsupported layouts. Direct SCM memory access was denied on the HP. The running Agent is therefore a same-boot launch witness, not a complete read of SCM memory. This scope assumes the trusted Agent and SCM do not rewrite their relevant environment after launch and no concurrent administrator changes installation or service configuration. It detects observed injection and accidental source mismatches, not historical injection that removed its own evidence. A stopped-only installation or lost witness is refused. Independent review must explicitly accept this boundary before live use; a stronger boundary needs a separately reviewed deterministic native launch/configuration design, not an assertion flag.

Before first start, a failure attempts to restore the original tree and restart the retained service; the protected backup remains. After a start is requested, the journal may have advanced. A failure then attempts to disable and gracefully stop the replacement, retains its current journal and the original backup, and needs operator reconciliation. Never copy the old snapshot over later authoritative state. An interrupted PowerShell process or power loss is not automatically reconciled: keep the protected original and inspect both paths and SCM state before any manual action. A Running status proves only a service state, not authentication. Verify a new authenticated check-in for the exact prior cabinet UUID and machine ID, approval/activity and nonempty historical data via supported API or Console. An expired credential requires the separate same-device renewal workflow, not another install or a new token.

The native `tests/office-bootstrap/Test-SameDeviceRecovery.ps1` fixture imports functions from the AST and uses disposable synthetic folders and a fake service adapter. `Test-RecoveryScmProbe.ps1` separately creates a unique inert service and verifies typed metadata, quoting and held-handle pending deletion, then exact cleanup. Its normal mode also attempts controlled delayed start/stop. `-MetadataOnly` never starts it and is not transition acceptance. Windows Application Control blocked the final newly compiled probe; do not disable or bypass that policy. Independent review, native transition rerun with an approved inert artifact, Windows 10 and explicit live authorization remain separate gates. No real Agent changes were made by these tests.

## Check the result

`Get-Service CabinetPlatformAgent` showing Running proves only a process started. Check `Get-CimInstance Win32_Service -Filter "Name='CabinetPlatformAgent'"` for `LocalSystem`, automatic start and the quoted fixed executable path. Check effective ACLs with `icacls` on the install folder and `office-enrollment.json.device` after first exchange. Read only redacted Agent logs in `logs` and verify its HTTPS contact. On the Console, a supervisor checks the pending queue, matches the expected machine identity and site, and explicitly approves it. Confirm the same cabinet ID survives an Agent restart and a fresh authenticated check-in appears after approval. Pending is not approved; approved is not proof that current diagnostics have arrived. Test a second unrelated machine/key denial in a lab before broader claims.

A refused token can mean it expired, the server was not restarted after issuance, the matching Office mode is not active, TLS failed, the machine identity already exists, or the manifest and durable grant journal disagree. Check those conditions without printing credentials. A lost HTTP response can be retried by the same persisted machine/key pair within the device deadline. An expired initial credential may use the reviewed manual same-device renewal only when its original key, approval, activity and history are retained; see demo-credential-renewal.md. Logs and service state do not substitute for an authenticated server readback. Preserve the exact error, package digest and source revision for review. Do not reset the journal or install over an identity.

For removal of an unused failed install, inspect whether the service and identity exist before acting. For an enrolled lab, the server operator first removes that device's token hash from the active manifest and restarts the reviewed test service under separate authorization. Confirm the old credential is rejected. Keep the consumed journal and cabinet audit history. Then stop and delete the lab service, retain a protected evidence copy of state if required, and remove its lab files according to retention policy. Do not delete a live installation, customer history or the HP Agent. Rollback to a shared-key server is not safe for this identity mode.

## Fleet deployment is separate

A production deployment across roughly 8,000 cabinets needs a signed installer, unattended deployment through an authorized management platform (platform not selected), per-device scoped onboarding and automatic credential renewal, safe updates and rollback with fleet status, and a reviewable revocation and recovery protocol. No shared fleet secret, remote session or manual script on every cabinet, and no unrestricted shell. This kit implements none of those production controls. Native Windows 10/11 install, ACL, PowerShell, WPF, TLS, refusal and removal checks remain an independent lab acceptance gate before distributing even the bounded demo kit.
