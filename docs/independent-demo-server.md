# Matching server and VPS operator steps

This kit includes source-bound Python issuance, renewal and read-only preflight tools. They are not a server deployment client. No service, database or live secret is changed by building the kit. Use the exact matching server revision in release-evidence.json and the server publish from the same commit. Do not run these steps on the live VPS until the owner verifies every path, unit name, configuration overlay, backup and maintenance window. The examples below are placeholders, not discovered live values.

## Before any activation

1. On the VPS, inventory the actual systemd unit with `systemctl cat <actual-unit>` and `systemctl show <actual-unit> -p User -p WorkingDirectory -p ExecStart -p Environment -p EnvironmentFiles`. Inspect the referenced environment files privately, including ASP.NET command-line arguments, appsettings and `office-enrollment.json` in the effective content root. Determine the actual database connection and journal absolute path. Do not paste secrets or credential hashes in evidence. Confirm TLS hostname and clock, one server process and private ownership. A health response is not evidence of Office mode or revision.
2. Verify the candidate server directory is the matched publish, not an old server. Record its full SHA-256 inventory out of band. Plan a compatible same-version rollback candidate that understands and preserves renewal history. The pre-renewal reader is not a safe writer after renewal. Preserve original database rows, consumed journal, manifest and all overlays. Do not use a pre-revocation snapshot to resurrect a grant.
3. Stop the actual unit gracefully in a separately authorized window. Confirm stopped and no process holds the journal. Make and verify a private, consistent backup of the database and the exact journal, manifest and effective configuration. Never initialize an empty journal, substitute a new server database or print secret values. Build a disposable protected rehearsal copy before migration.
4. The server loads `office-enrollment.json` optionally from its content root, after appsettings and before environment and command-line overrides. `OfficeEnrollment__Enabled=true` must also be pinned independently of that file. Missing tokens can start and shred existing bindings. The owner must establish the actual complete effective `OfficeEnrollment` snapshot, including final override precedence, and an explicit complete token inventory with approved revocations. This repository does not supply a trustworthy snapshot exporter for the live service. Do not fabricate `effective.json` from the manifest. If its provenance is not established, stop without starting the candidate.
5. On the stopped private copy, run `python3 office_renewal_preflight.py --manifest /private/office-enrollment.json --effective /private/effective.json --inventory /private/inventory.json --journal /private/grants.json`. Read demo-credential-renewal.md for the precise snapshot and inventory schema. Rehearse the corrected reader only on another protected disposable copy and compare all identity, renewal and tombstone history. Preflight is read-only and is not an activation permit. The exact final paths and configuration must be checked again before service start.
6. Only after the above gates and separate authorization, install the matched server publish into a new private candidate directory, preserve the current database and original journal, and start the actual service using the reviewed unit/working directory and effective configuration. Verify exact revision, old-key refusal, journal history, authenticated old Agent contact and previous history. A failed start requires keeping the protected journal and database intact and using only a compatible rollback candidate. Do not point the old pre-renewal writer at a renewed journal.

## Fresh disposable lab enrollment

After the matching server is safely active, run `python3 issue_office_enrollment.py --manifest /private/office-enrollment.json --output /private/new-device.json` as the service owner, using a new owner-only output path. It appends a token hash and writes the one-device secret, not a new journal. Recheck the actual effective configuration and authorize the test-service restart needed to load the new manifest before its 20-minute token expiry. Transfer the device JSON privately; do not put it in the published kit. A fresh installer is only for an authorized new machine identity. Use the Console supervisor queue to approve it, then verify a persisted same-ID check-in and history. The existing HP identity cannot pass as a fresh install.

## Repeat demo on the same original identity

Retain the protected Agent `.device` state. An approved, active device with prior history may request manual 24-hour renewal via `python3 office_renewal_operator.py --origin https://srv1522777.tail72f980.ts.net --username <supervisor> --cabinet-id <uuid> --machine-id <exact-id> --state /private/decision.json --reason 'specific lab session'`. Follow demo-credential-renewal.md for confirmation and exact-decision retry. No fresh token is required for a restored identity and no old journal or server rows may be discarded. This is bounded manual lab renewal, not fleet automation. A missing original key or suspected compromise is not a renewal case.
