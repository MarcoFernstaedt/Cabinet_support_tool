# Issue #35: absent-service same-identity recovery hold

**Status: NO-GO for any HP or Server write.** This protocol applies only when the HP service is absent (SCM 1060), the expected install tree is absent, and two protected copies of the *original* device journal and state survive. The differing incident copy is not a restoration source. No fresh enrollment, first-install helper, expired token, generated key, journal reset, ad hoc `sc create`, or experimental upgrade/manual reinstall is authorized. A missing `record.dpapi` is not a reason to bypass the manual helper's checks. Do not start a service against a possibly stale backup.

`tools/absent_service_recovery_preflight.py` is an **offline evidence-claim triage tool**, not a Windows host probe, provenance verifier or restorer. It does not read `.device` bytes, run SCM, connect to Server or write either host. Supply an operator-authored JSON file with the exact keys and shape of `tests/office-bootstrap/fixtures/absent-service-evidence.json` in a private directory. The sample digests are inert fixture values, **not HP evidence**. On POSIX the input file must be owner-only (0600); Windows ACL verification remains manual. Invoke `python3 -B tools/absent_service_recovery_preflight.py --evidence /private/evidence.json` on an offline workstation. Output contains only fixed reason codes, no source fields, paths, identity or digest values. Exit 2 and `NO_GO` are **intentional even if all fields assert true**. Invalid/unknown fields and duplicate JSON keys refuse. Keep the inventory private; do not attach real backup files or keys. The comparison of two operator-entered hashes is not a trusted hash measurement.

## Evidence required before designing a live restore

1. Preserve current HP disk/journals and original-copy/original-installed backups independently, with chain of custody, creation times, acquisition source, independently obtained SHA-256 for each original `.device`, state, executable and configuration file, and a verified immutable/secured storage location. Compare both originals byte-for-byte by independent read-only measurement; record differences in the incident copy without using it as source. A match alone cannot prove which copy is latest or genuine. Do not output any journal content, key material, token or customer diagnostic text.
2. Capture read-only Windows host evidence from a trusted elevated session: exact service absence and expected install absence, volume/path/reparse/owner and ancestor ACLs, original backup ACLs (including inherited ACEs and audit policy), identity of the physical host, and reliable **original** SCM binary path, service account, start type, failure/recovery actions, service security descriptor, dependencies and preshutdown settings from trusted pre-incident evidence. Service 1060 cannot reconstruct the old definition. Treat unknown provenance or ACL/SCM detail as a stop condition, not defaults to fill in.
3. Establish from protected source evidence the original machine/cabinet identity match, approved active Server binding and last authenticated contact. Privately inspect whether any journal advanced after backup acquisition or any attempted service start; if unknown, preserve both journals and reconcile rather than overwrite. Hash equality between backup copies cannot prove freshness. Resolve effective Server enrollment configuration, database and consumed-grant journal, revision/protocol compatibility with candidate Agent, and rollback reader compatibility. Verify consistent protected snapshot and restore rehearsal; never clear a grant or move backwards past revocation/renewal history.
4. Draft a separate, independently reviewed **absent-service** restore implementation: exact trusted package and original identity binding; reject reparse/writable parent, unsafe ACL, mismatched digest/SCM definition, present or partial service/tree, advanced journal, interruption and concurrent changes; secure destination *before* copying protected bytes; bound staging/rollback with no destruction of originals. Define partial SCM registration and start failure retention, deterministic stop/reconcile and no retry that silently replaces keys. This document and triage script implement **none** of these writes.
5. Prove the reviewed implementation on disposable native Windows with same absent-service/absent-install state: success, restart preserving identity, mismatched artifact, interrupted copy, partial registration, ACL/ancestor attacks, stale/advanced journal and recovery/rollback. Independent reviewer and QA must inspect exact revision and evidence; Linux synthetic tests do not certify Windows SCM/ACL behavior.
6. Only after the preceding gates, seek explicit maintenance approval for a compatible Agent/Server pair and protected Server snapshot, with rollback rehearsal and a brief bounded test-Server interruption. Read back intended LocalSystem SCM definition, private ACL, original identity, approval, fresh authenticated check-in and retained historical rows. Any uncertainty means stop, preserve current and original journals and reconcile offline. No browser Event Viewer exposure is authorized by this recovery step.

The triage `evidence` booleans mean **operator claims**, not certification. A false claim yields a named gap; true leaves the final independent-review/native-rehearsal blocker. The script never emits `SAFE`, `PASS` or a write command. Issue #35 remains open, as do W13/G05/G06/G08 release gates.
