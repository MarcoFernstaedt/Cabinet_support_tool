# Password demo BFF — source-only boundary

`CabinetPlatform.DemoBff` is a **separate demo-only** ASP.NET Core process. It does not modify the fail-closed Entra `CabinetPlatform.WebHost` and is **not** staff sign-in or product acceptance. Its routes are `GET /`, `POST /login`, `POST /logout`, `GET /cabinets/?id=<guid>`, `GET /cabinets/{id}`, and `GET /cabinets/{id}/performance`. It does not serve sample cabinet data or proxy arbitrary API paths. Cabinet pages read narrow Server projections under the live exact staff-to-cabinet grant check; they are not a fleet finder or general diagnostic view. The Node synthetic preview is separate and is not a fallback on failed Server login.

The BFF sends the submitted password over HTTPS to the existing Server `POST /api/auth/login`, whose account verification, lockout and IP limiting remain authoritative. It retains only the short-lived access JWT in an in-process, bounded session dictionary; it discards the upstream refresh token. The browser receives a random opaque `__Host-DemoSession` cookie (Secure, HttpOnly, SameSite=Strict, Path=/), never an API bearer. The server stores a digest of the cookie key. Sessions have an absolute expiry capped at the upstream access-token expiry and 15 minutes, plus a 10-minute idle cap; logout removes the server entry. Restart destroys all sessions. The session authenticates the staff bearer only; it grants no cabinet by itself. The Server rechecks the current staff account and exact cabinet grant for every detail request, including after grant revocation. The BFF never caches a cabinet response.

The host fails startup unless `DemoBff__PublicOrigin` and `DemoBff__ServerBaseUrl` are exact HTTPS origins. Bind the BFF HTTP listener **only to 127.0.0.1 or ::1** behind an operator-controlled HTTPS ingress such as tailnet-only Tailscale Serve; do not expose that listener on a tailnet or public address. It accepts exactly one `X-Forwarded-Proto` hop from a loopback proxy, checks resulting HTTPS scheme and exact Host against `PublicOrigin`, and never accepts forwarded Host or client IP. Direct unforwarded HTTP and forwarded headers from non-loopback peers are refused. Verify the proxy actually supplies `X-Forwarded-Proto: https`, preserves Host, and is absent from Funnel before showing real data. The Server must be accessible only through trusted network policy and certificate validation; do not expose its password API to an untrusted network. No development HTTP bypass, credential defaults, sample fallback, or embedded secret is provided. Form POSTs require both exact Origin and ASP.NET antiforgery validation; ingress POSTs are rate-limited per observed remote IP (one shared loopback partition behind this proxy), with no trust in `X-Forwarded-For`. Browser-visible denials do not contain account status, passwords or Server error bodies.

This does **not** implement MFA, Conditional Access, a public grant-management UI, password-change UX, distributed session storage, fleet listing, Event Viewer projections, or verified HP-backed data. It does include a bounded latest-performance page when the matching Server has an accepted Agent heartbeat and a live exact grant. Staff deactivation and grant revocation are enforced by the Server on every cabinet read, while the in-memory BFF cookie may remain present until its short expiry or logout; an unauthorized detail is denied rather than rendered. Before real cabinet data, independently validate grant provisioning and revocation, privacy/retention and audit, TLS ingress, credential-rate-limit partitioning behind an approved proxy, browser accessibility, and native Windows/HP acceptance. No live Server/HP credentials or deployments are used in these source tests.
