# Cabinet agent adversarial audit

Reviewed revision `d2511426f9deef0a16954b8f490dcedb26936f66` on `main` (read-only; unrelated dirty `deploy/compose.yaml` and untracked `deploy/Caddyfile.local` were not touched). Static inspection on Linux, not Windows execution. Scope inventory included agent source, contracts, tests and all six PowerShell scripts; findings below trace the security-critical paths, but this is **not** a claim that every source and test file received line-by-line review. No Windows service, WMI, installer or upgrade was executed. Paths are relative to repository root. “Proved” means the control flow is explicit in the cited source; exploit conditions or Windows-specific outcomes marked “Hypothesis” need a Windows reproducer. Ranked by severity and consequence.

## Findings

1. **High — Broker does not authenticate command provenance or authorization. Proved.** `agent/src/Cabinet.Agent.Core/BrokerProtocol.cs:154-168`: `bool write = Catalog.TryGet(request.Operation, out CatalogEntry entry) && entry.Kind == OperationKind.Write; ... OperationRunner.RunAsync(_registry, request.Operation!, request.Params!.Value, limit, token)`. The pipe authenticates the network-service account, but a compromised network process can mint any `commandId`, call any catalog write (including reboot, driver removal, firewall disable), call `confirm`, or replace the watch list without proving receipt of an authorized server command. Read-only mode and rate limiting are not command authorization. **Fix:** bind each privileged request to broker-verifiable, authenticated, non-replayable command authorization and independently enforce operation/role permissions; do not treat pipe SID or UUID as authority. This is a security-design gap, not a claim that a remote attacker already controls the network service.

2. **High — Failed rollback is durably recorded as successful and never retried. Proved.** `agent/src/Cabinet.Agent.Core/Writes/SafetyNet.cs:114-125`: `catch (Exception ex) { ... } s.Pending.Remove(e); Record(s, e.CommandId, SafetyNetState.RolledBack);`. If WMI/firewall restore throws, the actual unsafe setting persists while the pending entry disappears and `confirm` reports `rolled_back`. **Fix:** retain failed entries with retry state, distinguish rollback failure from completion, and only record `RolledBack` after verified restoration.

3. **High — Network/DNS and firewall changes are applied before durable rollback protection. Proved.** `agent/src/Cabinet.Agent.Core/Writes/BrokerWrites.cs:103-108`: `network.SetDns(...); DateTimeOffset deadline = safetyNet.Arm(...)`; also `:49-53`, `:138-145`, `:167-182`, `:213-226`, `:238-241`. A process kill, disk error or post-change read/journal failure between these statements leaves the change applied with no pending safety-net entry; `SetDns` and `Restore` do not even call `ArmIfPartlyApplied` on a throwing Windows call. **Fix:** persist a pre-change rollback intent before invoking Windows, transition it durably after applying, and restore immediately or retain retryable intent on any failure.

4. **High — Expired safety-net change can be confirmed and kept before the five-second tick. Proved.** `agent/src/Cabinet.Agent.Core/Writes/SafetyNet.cs:79-86`: `if (pending is not null) { s.Pending.Remove(pending); Record(s, commandId, SafetyNetState.Kept); ... }`. `Confirm` never checks `pending.Deadline`; confirmation just after two minutes but before upkeep runs suppresses rollback permanently. **Fix:** compare deadline to current time under the same synchronization and perform/require rollback before returning `Kept` for expired entries.

5. **High — Firewall auto-reenable timer is deleted before reenable succeeds. Proved.** `agent/src/Cabinet.Agent.Core/Writes/FirewallStore.cs:103-109`: `t.Items.RemoveAll(i => i.ReenableAt <= now); _timers.Save(t);`; `agent/src/Cabinet.Agent.Core/Writes/BrokerWrites.cs:264-276` only re-adds the timer in the exception handler. If the broker exits between the persisted removal and `firewall.SetProfile(..., true, ...)`, the disabled firewall profile stays off indefinitely. **Fix:** leave due timers durable until a successful, verified reenable; then remove them.

6. **High — Source trust check ignores writable descendant files and many writable principals. Proved check gap; exploit is conditional.** `agent/install/Install-CabinetAgent.ps1:56-65`: `$broad = @('S-1-1-0', 'S-1-5-11', 'S-1-5-32-545')` and loop `Get-ChildItem ... -Directory`; `:69` checks signatures, then `:101` copies executables. File-specific ACLs and any other writable SID (e.g. a local group or explicit service principal) are not rejected; a mutable file can also change between signature check and copy. **Hypothesis:** an attacker with such write access could replace LocalSystem broker bytes, particularly under `-AllowUnsigned`; a Windows ACL/TOCTOU reproducer is needed. **Fix:** stage into a new administrator-only directory, validate the copied artifacts and every ancestor/file ACL and signature there, and atomically install from that immutable staging directory.

7. **High — Installer rewrites existing installation in place with no rollback. Proved.** `agent/install/Install-CabinetAgent.ps1:99-101`: `Stop-Service ...; New-Item ...; Copy-Item ... -Recurse -Force`; `:198-199` starts services only at the end. A failed or interrupted copy leaves mixed binaries and stopped services; old files not present in the new source remain, and a rerun can mix versions again. **Fix:** preflight all inputs, copy to a separate locked version directory, verify it, swap with a retained backup, and restore the previous files/services on failure.

8. **High — Upgrade failure is marked final even when restoration failed. Proved.** `agent/src/Cabinet.Agent.Core/Upgrades/Updater.cs:185-196`: after a failed restore, `return journal.Write(j with { Phase = UpgradePhase.Failed, ... })`; `:126-127`: `if (j is null || j.Final) return j;`. A transient locked file or service failure during rollback leaves a broken install, yet startup will not retry restoration. **Fix:** retain a non-final restore-pending journal phase until the backup is restored and both services are verified running.

9. **High — A corrupt or unreadable safety-net state silently becomes empty. Proved.** `agent/src/Cabinet.Agent.Core/Monitoring/StateFile.cs:19-25`: `if (!File.Exists(_path)) return new T(); ... catch (...) { return new T(); }`; `agent/src/Cabinet.Agent.Core/Writes/SafetyNet.cs:51-55,106-110` uses it for pending rollbacks. A truncated/damaged `safety-net` file converts active network/firewall rollback obligations into no obligations at restart. **Fix:** fail closed on unreadable critical state, preserve a recoverable previous copy and alert; reserve fresh-state fallback for non-safety monitor caches.

10. **Medium — Broker keeps a download directory after failed recreation without validating its ACL or ownership. Proved fallback; exploit conditional.** `agent/src/Cabinet.Agent.Broker/Program.cs:130-144`: after deletion/create fails, it logs `keeping it` and checks only `ReparsePoint`. If an existing folder has broadened ACLs, the broker proceeds to read packages/releases through it; verification may prevent execution of unsigned code, but trust-boundary assumptions about the staging source and availability are weakened. **Fix:** verify owner, DACL and parent integrity on fallback and fail closed if the directory cannot be rebuilt securely.

11. **Medium — Installer overwrites cabinet identity and enrollment state on every rerun. Proved.** `agent/install/Install-CabinetAgent.ps1:23,161-176,190-194`: `[guid] $CabinetId = [guid]::NewGuid()` and unconditional `WriteAllText($configPath, $json)` / bootstrap-token write. A repair or upgrade with default parameters silently assigns a new cabinet ID, nulls server settings and can leave the original certificate/key tied to another ID, stranding enrollment. **Fix:** detect existing installation and preserve identity/configuration by default; require an explicit re-enrollment path to replace them.

12. **Medium — Result is forgotten after server acceptance even if local delivery marker cannot be saved. Proved.** `agent/src/Cabinet.Agent.Core/Server/ResultOutbox.cs:133-143`: `Forget(commandId); ... File.Move(...); ... catch (...) { TryDelete(PendingPath(commandId)); }`. If move to `done` fails after a 2xx/409, the only durable copy can be deleted; when the server reoffers a command after a lost poll/lease, the agent cannot answer from the outbox. **Fix:** keep the pending file and in-memory index until the `done` move is durable; retry the transition on failure.

13. **Medium — Requeue drops delivered index before confirming file move. Proved.** `agent/src/Cabinet.Agent.Core/Server/ResultOutbox.cs:98-105`: `if (!_delivered.Remove(commandId)) return false; try { File.Move(...) } catch (...) { return false; }`. A sharing violation or disk error returns false while forgetting a valid delivered result for the rest of this process lifetime. **Fix:** perform the move first and remove `_delivered` only after success.

14. **Medium — WMI adapter calls have no explicit COM timeout and outlive operation cancellation. Proved.** `agent/src/Cabinet.Agent.Windows/NetworkControl.cs:17-18,54-60`: `searcher.Get()` and `a.InvokeMethod(method, input, null)` use no bounded `ManagementOptions`; `agent/src/Cabinet.Agent.Core/Operations.cs:120-125` merely stops awaiting a timed-out worker. A hung WMI provider leaves privileged work running after a timeout, holds `BrokerWrites._gate`, and can later apply a network change without an acknowledged command; repeated calls exhaust workers. **Fix:** set bounded WMI operation options where supported and isolate/serialize changes so cancellation cannot report final failure while privileged mutations remain in flight; test a hung provider on Windows.

15. **Medium — Network static-IP operation swallows failure to remove an old gateway. Proved.** `agent/src/Cabinet.Agent.Windows/NetworkControl.cs:74-76`: `try { Invoke(a, "SetGateways", ... empty ...) } catch (Core.OperationFailedException) { }`. On Windows builds that reject empty gateways (the comment acknowledges this), a supposedly gateway-free static configuration retains the previous router and returns success. **Fix:** use a supported gateway-clearing API or fail and roll back when the requested postcondition cannot be achieved; verify after state.

16. **Medium — Uninstall claims success after suppressed stop/delete/file failures. Proved.** `agent/install/Uninstall-CabinetAgent.ps1:11-19,26`: `Stop-Service ... -ErrorAction SilentlyContinue`, unchecked `sc delete`, and `Remove-Item ... -ErrorAction SilentlyContinue`, followed by `Write-Host 'Cabinet agent removed.'`. If service stop/delete or file removal fails, services or binaries survive while the script says they are removed; `-RemoveData` can then delete state/key for a still-running service. **Fix:** check `sc.exe` exit codes and service disappearance, make deletion errors terminating, and only remove state/key after confirmed service stop/removal.

17. **Medium — 32-bit PowerShell resolves System32 and Program Files differently. Proved path usage; Windows outcome conditional.** `agent/install/Install-CabinetAgent.ps1:85-87`: `$programDir = Join-Path $env:ProgramFiles ...; $sc = Join-Path $env:SystemRoot 'System32\sc.exe'`; uninstall repeats these at `:8,15-19`. Running elevated 32-bit PowerShell can resolve `$env:ProgramFiles` to the x86 tree and redirect `System32`; installation/removal can act on a different tree from the x64 updater/agent paths. **Fix:** require 64-bit process at startup (or relaunch explicitly via Sysnative), and use one canonical 64-bit installation path in all scripts and binaries.

18. **Medium — Release signing/trust scripts use .NET APIs and PowerShell constructs absent in Windows PowerShell 5.1 without a version guard. Proved source; runtime failure is a compatibility hypothesis.** `agent/install/New-UpgradeTrust.ps1:42-45,78,93`: `ImportFromPem`, `[Convert]::ToHexString(...)`, `-Encoding utf8NoBOM`; `agent/install/New-AgentRelease.ps1:57,61,80-81,107,111` uses the same newer APIs. On stock Windows PowerShell 5.1 / .NET Framework these scripts fail after beginning output creation (possibly after writing a private key). **Fix:** explicitly require PowerShell 7 and compatible .NET before side effects, or implement 5.1-compatible primitives.

19. **Medium — Release builder skips Authenticode validation outside Windows even for production signers. Proved.** `agent/install/New-AgentRelease.ps1:40-45`: `if ($IsWindows -and -not $AllowUnsignedForTest) ... else { Write-Warning 'Authenticode cannot be checked...' }`. A Linux/macOS production pipeline can sign a release manifest with KMS around unsigned binaries; only the endpoint discovers the invalid artifact, causing rollout refusal after download. **Fix:** fail closed for production signers unless the build environment can verify Authenticode (and distinguish deliberate dev-key negative tests).

20. **Medium — CA fingerprint is optional during connected install. Proved.** `agent/install/Install-CabinetAgent.ps1:75-80`: `elseif ($PlatformCaFile) { Write-Warning 'No -PlatformCaSha256 given: the platform CA file was not checked against the console.' }`. A substituted CA file can be pinned as the server's trust anchor without out-of-band verification; TLS alone cannot detect a maliciously supplied anchor. **Fix:** require `-PlatformCaSha256` whenever `-PlatformCaFile` or a platform endpoint is supplied, and abort on omission/mismatch.

21. **Low — Source key path protection uses a string prefix rather than a path boundary. Proved.** `agent/install/New-UpgradeTrust.ps1:35-36`: `if ($full.StartsWith($repo, [StringComparison]::OrdinalIgnoreCase))`. A private-key path in a sibling whose name begins with the repo name is rejected despite being outside it; conversely reparse-point resolution is not proved by this string check. **Fix:** compare canonical resolved path components against the repository root, account for symlinks/reparse points, and refuse ambiguous paths.

## Fix first

1. Broker-side authorization/provenance for privileged requests (#1).
2. Keep failed rollback obligations and report their real state (#2, #9).
3. Persist rollback intent before any network/firewall mutation; enforce deadline at confirm (#3, #4).
4. Make firewall reenable timers durable through successful application (#5).
5. Stage and verify immutable, ACL-locked installation artifacts and provide transactional installer rollback (#6, #7).

Static source evidence only; particularly ACL race, 32-bit redirection, PowerShell 5.1 and hung WMI conditions require disposable Windows 10 and Windows 11 verification. No repository file was changed, and no state-changing command or dependency install was run.
