# Sync connectivity firewall clue

The site connectivity queue shows an automatic, read-only source cabinet check when three consecutive scheduled ICMP probes to the approved sync cabinet receive no reply. One check runs per continuous failure run; a reply or local probe error resets that run. The automatic path reads profiles only, never enumerates firewall rules, and waits at most two seconds so it does not hold up later probes. A native COM call itself cannot be interrupted; one in-flight check per Agent process is allowed, and a still-running read makes later checks unavailable rather than spawning more native work. No arbitrary destination can request this inspection, and it changes no firewall settings. The check is added to the same bounded interval evidence sent through the Agent spool and authenticated Server ingestion. It reaches the queue after the evidence is delivered, so an uplink outage can delay the alert.

The queue's **Source firewall clue (not cause)** label has three outcomes:

- **Possible source outbound firewall block:** An active Windows firewall profile on the probing cabinet is enabled and its default outbound action is Block. This makes a source firewall issue plausible, but an explicit allow rule or the actual packet path may tell a different story.
- **No coarse source outbound block seen:** All active source profiles were read, with no enabled default outbound Block. This is a negative result for this narrow profile check, not proof that a firewall is uninvolved. Individual source rules, target inbound policy, upstream devices and other causes remain unchecked.
- **Unknown:** The source check did not run, the native read was incomplete, or the active profile actions could not be evaluated. The incident remains actionable without this clue.

The selected incident displays the source check time in MST. The check never collects the sync cabinet's database, diagnoses effective packet permission, inspects the target cabinet automatically, or makes configuration changes. Support can open the source and measured target for further read-only inspection and may make approved configuration changes through separate operator controls. A failed ICMP probe alone never establishes the cause.

The Console supports both an all-sites queue and a site-scoped queue. From a loaded cabinet, **Site alerts** opens incidents for that cabinet's site; a selected incident can also be scoped to its source site, and **Show all sites** clears the filter. Filtering uses the source cabinet's site ID, not a display name or the target cabinet's site. It is applied by the authenticated Server query before pagination, with the scope displayed above the queue. Switching scopes clears the previous selection and cancels a stale in-flight refresh. This is a support-wide view, not per-site authorization; the site label reflects the source cabinet's current site association.

A synthetic integration test now exercises Office per-device enrollment, approval, restart, real Agent credential transport, a designated sync target, three injected no-reply probes, an injected read-only source result, local spool survival during a simulated uplink failure, authenticated ingestion and site-scoped Console alert retrieval. It also checks that a later recovery does not turn the historical clue into a current cause verdict. This proves the application path under injected native inputs, not native Windows firewall behavior, real ICMP, network outage durability or a deployed Console.

The payload is an optional field in the existing versioned interval JSON. Older evidence appears as Unknown. Evidence linked to a retained alert is kept with that alert for at most 30 days and 200 alerts per source; ordinary evidence still uses the shorter retention policy. Linux synthetic tests and a Windows-targeted cross-build do not satisfy those gates.
