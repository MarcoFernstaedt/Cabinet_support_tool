# Sync connectivity firewall clue

This describes **retained historical incident evidence**, not an active probe or
automatic inspection. Scheduled cabinet-to-sync ICMP and authenticated interval
summary ingestion are retired. Old accepted intervals and alerts remain readable;
no new source firewall clue is produced by scheduled peer probes. A historical
clue is not a current firewall verdict.

The queue's **Source firewall clue (not cause)** label has three outcomes:

- **Possible source outbound firewall block:** An active Windows firewall profile on the probing cabinet is enabled and its default outbound action is Block. This makes a source firewall issue plausible, but an explicit allow rule or the actual packet path may tell a different story.
- **No coarse source outbound block seen:** All active source profiles were read, with no enabled default outbound Block. This is a negative result for this narrow profile check, not proof that a firewall is uninvolved. Individual source rules, target inbound policy, upstream devices and other causes remain unchecked.
- **Unknown:** The source check did not run, the native read was incomplete, or the active profile actions could not be evaluated. The incident remains actionable without this clue.

The selected incident can expand its accepted historical interval: first and last measurement times, replies, nonreplies, local probe errors, longest failure run, last reply and nonreply, and approved plan revision. The evidence is joined to the alert by evidence ID, source ID and measured target ID. Missing retained evidence is shown as unavailable and unknown, not as zero counts or current health. These facts do not establish the cause of a failed ping. The check never collects the sync cabinet's database, diagnoses effective packet permission, inspects the target cabinet automatically, or makes configuration changes. Support can open the source and measured target for further read-only inspection and may make approved configuration changes through separate operator controls. A failed ICMP probe alone never establishes the cause.

The Console supports all-sites, site-scoped and source-cabinet-scoped queues. The site queue also shows a server-timed historical operator workload summary for the source site's retained 30-day incidents: open, acknowledged and resolved. The grouped Server query counts across every queue page and includes resolved incidents even when that checkbox is off. The summary refreshes after an annotation or queue refresh and disappears when switching to cabinet or global scope. A slow or failed summary does not block a successfully loaded queue; its count stays unknown and a failed request is shown. These statuses are workflow annotations, not an outage count, sync application status or current site health. From a loaded cabinet, **Site alerts** opens incidents for its site; **Cabinet alerts** opens only incidents sourced by that exact cabinet ID, even if a peer shares the same name. A selected incident can be scoped to its source site, and **Show all sites** clears either filter. The authenticated Server filters before pagination. Scope is visible above the queue, and switching scope clears the previous selection and supersedes in-flight results. Site membership reflects current source-cabinet data, not an immutable incident-time snapshot. This is a support-wide view, not per-site authorization; the site label reflects the source cabinet's current site association.

A historical synthetic integration test exercised Office per-device enrollment, approval, restart, real Agent credential transport, a designated sync target, three injected no-reply probes, an injected read-only source result, local spool survival during a simulated uplink failure, authenticated ingestion and site-scoped Console alert retrieval. It also checks that a later recovery does not turn the historical clue into a current cause verdict. That test demonstrated the former application path under injected native inputs, not native Windows firewall behavior, real ICMP, network outage durability or a deployed Console.

The payload is an optional field in the existing versioned interval JSON. Older evidence appears as Unknown. Evidence linked to a retained alert is kept with that alert for at most 30 days and 200 alerts per source; ordinary evidence still uses the shorter retention policy. The historical synthetic test is not evidence of current delivery or native Windows behavior. The current web-only delivery still requires its own native Windows, browser, authorization and deployment acceptance gates.
