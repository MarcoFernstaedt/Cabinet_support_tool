# Cabinet Support delivery register

This is a finite planning baseline, not a claim that the 82 vision sections are 82 independent features. **21 operator workflows** are in scope in this register. A workflow is a bounded support outcome with a visible entry point, authorized data path, failure states and a testable acceptance result. Split or rebaseline it explicitly if the requirements change. The web app is the primary Console; WPF is a transitional compatibility surface. Remote screen/control, arbitrary shell, patient or application database access, physical actuation and automatic firewall repair are excluded. Privileged repairs and file handling need separate approval before implementation.

**Build sequence:** Finish the source implementation across this register in bounded, independently reviewed web-first slices. Follow with consolidated manual Windows/device/browser testing and visual polish, then staff and production hardening. Automated synthetic tests, security review and CI remain gates for every source merge, not tasks deferred until manual QA. A workflow can remain partial while an evidence source or approval is missing; record that honestly and continue the build queue. Do not activate staff access or privileged control merely because source exists.

**Status rule:** `source merged` means reviewed code is on `main`, not deployed or production accepted. `planned` means no acceptance claim. A workflow becomes `accepted` only after identity, security, native Windows/browser, fleet, deployment and operator gates relevant to that workflow are evidenced. The local password gateway is loopback-only, has no MFA and may use synthetic accounts only. The separate Entra host has no cabinet data routes. Never expose cabinet data to staff through either as though production auth were complete.

## Delivery sequence

### Incident triage source, WPF transitional
1. **Cabinet incident queue** | Source merged, PR #7 | From a loaded cabinet, open incidents scoped to its immutable ID, with empty/error and stale-scope handling. Native UI and deployment acceptance open.
2. **Incident evidence detail** | Source merged, PR #8 | Open accepted historical interval evidence with timestamps, counts and explicit unknowns; never infer live connectivity or firewall cause. Native UI and device acceptance open.
3. **Site incident annotation workload** | Source merged, PR #9 | Show retained status totals across the current source site, query time and unknown on summary failure without hiding the queue. PostgreSQL fleet latency and native UI acceptance open.

### Web Console, local development preview source
4. **Web cabinet finder** | Local preview source, release blocked | Staff searches a bounded, paginated cabinet list, sees site/client and freshness, and cannot leak bearer credentials into browser JavaScript. The local password gateway is only for disposable synthetic data; production requires Entra staff mapping and authorized BFF, deny/revocation tests, real fleet pagination and accessible browser QA.
5. **Web cabinet detail** | Local preview source, release blocked | Open the exact selected cabinet ID from the finder, show site/sync identity and timestamped historical health; handle inactive, denied, missing and stale navigation distinctly. Same identity and release gates as #4.
6. **Web site incident queue** | Local preview source, release blocked | From the selected cabinet's site, read a bounded incident page and server-timed site workload, inspect historical evidence and preserve uncertainty. A failed optional count must not blank the page. Same identity and release gates as #4 plus PostgreSQL plan/latency.

### Read-only diagnosis and monitoring
7. **Web Event Viewer connected result** | Local preview source, release blocked | Read the latest bounded saved Agent Event Viewer action for the exact cabinet through a narrow server projection, with channel/provider drilldowns, per-channel outcomes, request and Agent-reported completion times, truncation and explicit pending/failed/partial states. No generic action-output browser proxy, no fictional records in connected mode. Production identity and cabinet authorization, Windows native collection, actual transport, representative query plan, security and browser accessibility gates remain open.
8. **Application crash investigation** | Partial local preview source, release blocked | From a cabinet, inspect bounded saved Application Error 1000 and WER 1001 event clues plus a separate, on-demand machine WER queue/archive metadata observation. A further parameterless, read-only Agent action samples at most 64 recorded local Security 4688/4689 process starts and exits in a fixed recent window, preserving time, numeric PID, event kind and optional local record number through strict Server ingestion and cabinet/action-pinned projection. This is not a process inventory at crash time: auditing may never have been enabled or continuously retained; empty results and missing exits do not prove a process was present or absent. PID reuse, reboot and incomplete coverage forbid automatic pairing. WER creation time is not crash time, nearby records are not necessarily one incident, and no cause is inferred. No command line, path, SID, username, rendered Security text, raw XML, WER file or report signature is exposed by these narrow projections. Native Windows service-context collection, child termination, audit coverage, privacy/retention policy, browser accessibility, scoped staff authorization and production identity remain open.
9. **Process and service diagnostics** | Local preview source, release blocked | From a cabinet, inspect an exact bounded saved `GetProcessList` action with pinning, pending/failed/truncated states and counter unknowns; separately inspect retained service inventory with first/last observation times. Process completion is not a sample instant. Unchanged inventory can retain an old service PID, so the web page does not display or join service PIDs to process rows. No start, stop, kill or other controls. Native Windows transport, current-vs-retained service semantics, privacy, browser accessibility and staff authorization remain acceptance gates.
10. **Fleet and site health overview** | Local preview source, release blocked | Paginate active cabinets and sites with stable global site ordering, separate last contact from latest heartbeat collection/receipt, and count missing/stale measurements separately from health and stale contact. Unknown is not Healthy, a standalone site has no sync relationship, and historical probe nonreply is not firewall proof. Source tests and local preview do not establish PostgreSQL fleet latency, cross-request snapshot consistency, browser accessibility, Windows transport or staff authorization.
11. **Connectivity incident correlation** | Local preview source, release blocked | Open exact accepted source-to-target ICMP interval from a retained alert; show source and target server contact and separately timed heartbeat measurements, current sync topology and optional coarse source firewall clue. Missing evidence remains unknown. Operator resolution is not measured recovery, ICMP nonreply does not diagnose a firewall, and application-port evidence is not collected. Manual transport, privacy, authorization and browser acceptance remain open.
12. **Network history** | Local preview source, release blocked | Traverse bounded retained, accepted source-to-target ICMP intervals by observed-time cursor with Agent observation and Server receipt separated; show replies, nonreplies, local probe errors and uncertain gaps without inferring outage duration or exact recovery onset. Retention and late replay prevent a completeness guarantee. Native transport, fleet-scale PostgreSQL query latency, browser accessibility and staff authorization remain open.
13. **Storage and SMART investigation** | Partial local preview source, release blocked | Inspect the exact cabinet's bounded heartbeat disk summary, historical volume free-space observations and newest retained SMART reading per reported serial. Open a cabinet-bound opaque drive selector for a bounded, paged SMART trend with collection time, nullable Server receipt for newly accepted rows, and explicit unknown receipt for legacy rows and daily rollups. Date inventory-embedded values to the version's first observation, keep absent counters unknown rather than zero, and label retention, late delivery and dominant rather than per-counter SMART source. A serial groups reports but does not prove physical-drive continuity; lettered volumes are not linked to a particular drive over time. No fabricated failure prediction. Native Windows collection and transport, browser accessibility, scoped staff authorization, deployment key persistence and production identity remain open. Synthetic PostgreSQL query and migration checks do not establish fleet production latency.
14. **Restricted log explorer** | Blocked, no source merged | Agent rolling Serilog files are identifiable as a candidate but the configured sink cannot yet be bound to the separate log-directory setting. Existing diagnostic ZIP collection is not a safe reader: it lacks reviewed redaction and can include sensitive content. A local Agent-only refusal scaffold remains unmerged. Require an owned fixed source, reparse-safe file identity, approved privacy/redaction and retention policy, bounded Agent-to-Server validation, staff authorization and native Windows tests before list/read UI or log text. No arbitrary paths or raw ZIP proxy.
15. **Display diagnosis** | Partial local preview source, release blocked | Read a saved, cabinet/action-pinned Agent observation of up to eight OS display modes visible to the service, with measured time, unavailable/denied states and truncation. Interactive-user scaling, Magnifier and application zoom remain separately unmeasured or inaccessible, not inferred from mode dimensions. This is not proof of the active user's effective resolution; no correction or remote access is available. Native Windows service/session behavior, retained action-result privacy, browser accessibility, staff authorization and production identity remain open.

### Operator administration and controlled change, separately authorized
16. **Cabinet enrollment and retirement** | Partial local preview source, release blocked | A Supervisor can review a paged pending queue and exact identity, choose client/site/role, approve with an audited reason, reject with a reason, and confirm retirement of an exact cabinet after a fresh identity/site/role read. The Server owns transactional pending-decision conflicts and operational retirement with audit. Office-mode retirement now commits SQL inactivity before persisting a journal tombstone that replaces the device key hash; failed journal writes return a retryable error while SQL authentication denies the retired identity. Repeated retirement repairs the journal without repeating the retirement audit, and startup reconciles inactive identities before listening. SQL and journal writes are not atomic, and restoring both from pre-retirement backups can restore authority. Legacy fleet-wide shared keys require rotation to revoke the secret. A fresh web read is not an atomic write precondition; simultaneous retirement attribution is unproven. Native Agent/Server transport, scoped staff authorization, MFA, browser accessibility, backup/restore policy and production acceptance remain open.
17. **Staff and session administration** | Planned for web | Review scoped staff identities, roles and revocation with least privilege and independent authorization; Entra mapping and MFA are prerequisite.
18. **Approved file staging and receipt** | Planned | Select exact targets, stage signed/approved files and distinguish server receipt, Agent receipt and verified local staging; no installer execution.
19. **Process lifecycle maintenance** | Planned, approval required | Select a creation-verified process or approved application session, preview impact, obtain authorization, record unknown outcomes and prove inert Windows recovery.
20. **Network and display recovery** | Planned, approval required | Apply only narrow approved changes with durable prior state, independent access and timed revert; no automatic firewall repair.
21. **Approved update deployment** | Planned, approval required | Target signed compatible packages in maintenance windows, verify version/reboot and recover interrupted installations; never treat file delivery as execution authority.

## Cross-cutting release gates

For each slice record the commit, supported OS/browser, threat boundary, role and cabinet/site authority, test counts, review, failure/revocation/restart behavior, real Agent-to-Server-to-web data evidence where applicable, query plan at representative fleet size, accessibility and Windows 10/11 acceptance, rollout and rollback. These gates are not implicitly passed by a source merge, mock, synthetic test, Linux cross-build or green CI. The current web sign-in and synthetic Event Viewer must not be used for staff or production cabinet data. Native and physical-cabinet checks remain blocked while the HP is offline.

The vision index and `docs/readiness.md` remain requirements and release-gate references. This register is the countable delivery queue; new requests change the baseline only with an explicit new entry and acceptance criteria.
